## 3. Candidate endpoint and context route

The draft targets one patient-level conditional configuration task. For one
future admitted patient record:

- `z` contains the exact patient/group identity used only for custody and
  splitting plus the future frozen static admission descriptors; static fields
  are never generated events;
- `Y` is the complete admitted multiset-like configuration of time-series
  measurement rows on the declared 0--2,880 elapsed-minute horizon; and
- `A` is an unordered partial observation of `Y` generated by a future frozen,
  application-justified observation kernel.

This is a route, not the populated scientific semantics required by F023--F035.
The event vocabulary, type IDs, units, scalar supports, missing sentinels,
observation mechanism, detection/confusion/clutter rules, reference measure,
and positive/common-support parameters remain typed future receipts.

The bound local code supplies the following draft invariants:

1. raw input is exactly `Time,Parameter,Value` with lossless decoded rows;
2. the declared local horizon is 48 hours or 2,880 elapsed minutes;
3. `RecordID`, `Age`, `Gender`, `Height`, `ICUType`, and admission `Weight`
   are static descriptor names in the current local code receipt;
4. later `Weight` rows are the sole locally declared dual-role exception;
5. physical time is an atomic minute grid and simultaneous measurements are
   preserved;
6. no sort, imputation, deduplication, row collapse, timestamp jitter, or
   synthetic tie-break is silently permitted;
7. every admitted observation row maps to one event or the whole patient
   conversion fails; and
8. missing values remain missing marks rather than being imputed into `Y`.

The first four items are code-receipt facts, not official-source verification.
Every one must be reconciled with a later content-addressed source/schema
receipt before a scientific field can close.

## 4. Fail-closed population pipeline

After a separately admitted precontact protocol, fresh authority, and lawful
data access, the route requires the following serial stages:

1. bind the official immutable archive, source version, raw hash, byte count,
   license, governance determination, and permitted-use controls;
2. inventory only explicitly allowlisted record files—never discover files by
   a broad glob—and keep outcomes or neighboring files outside the record
   inventory;
3. verify unique patient identity and source-partition disjointness without
   assigning modeling split roles;
4. apply the separately reviewed patient-ordering and split-manifest package;
   this package deliberately defines no patient hash, domain separator,
   collision rule, allocation, or split execution;
5. learn the event vocabulary, support metadata, normalization, caps, and any
   data-dependent transform on training patients only;
6. freeze one complete adapter policy, with an exact version and manifest
   digest, before validation or test access;
7. run the method-blind training-only admission audit; and
8. admit the domain only if every hard invariant and the frozen statistical
   threshold passes without exclusion, resplitting, noise invented for theorem
   convenience, or post-outcome repair.

Any missing, ambiguous, inconsistent, nonrepresentable, cross-partition,
unapproved, or unbound record makes the relevant stage `NO_GO`. No patient or
row may be quarantined merely to make the task feasible.

## 5. Observation and common-support route

The clean scientific observation kernel must be justified by how measurements
are actually observed in the application. The task may not add detection
noise, confusion, clutter, missingness, clipping, or full-support contamination
solely to satisfy a theorem.

The selected development policy remains the Solo-Block-2 route:
`ACQUISITION_JUSTIFIED_POSITIVE_DOMINATED_MIXTURE_WITH_SHARED_BASE_STRUCTURAL_ZEROS_AND_FAIL_CLOSED_NONADMISSION`.
For PhysioNet this means a future admitted task must:

- keep the clean kernel separate;
- freeze a normalized observation reference and positive mixture weight only
  if the acquisition model justifies them;
- use the same frozen unconditional base generator for exact and plug-in laws;
- preserve shared base structural zeros;
- prove finite positive information and normalizers on every occupiable state;
- keep every target-positive occupied edge candidate-positive; and
- terminate with domain nonadmission if those obligations fail.

No reference, mixture weight, support proof, or domain verification exists in
this package. F032--F035 remain null and open.

## 6. Method-blind training-only admission draft

The future admission artifact must report a fixed vector before test access:

- raw-format and identity failures;
- unknown or unbound parameter rows;
- unresolved static or event missing-sentinel semantics;
- event-state collisions under the exact row-preserving adapter;
- horizon, support, cap, and overflow violations;
- row or patient exclusion count;
- patient overlap across source or modeling partitions;
- clean-kernel normalization and common-support certificate failures; and
- exact counts and denominators for every component.

Hard integrity components must be zero. A separate, pre-outcome statistical
component and threshold may be selected only from training patients and must
be method-blind. This draft does not choose that statistic or threshold, so
F036 and F037 remain null. Validation or test patients cannot repair, tune, or
replace a failed training admission rule.

## 7. Split and custody seam

Patient grouping is exactly by future canonical `RecordID`; all rows for one
patient remain in one split. The split manifest must be content-addressed and
patient-disjoint before development exposure. The exact ordering/hash design
belongs to a separate package. This package neither duplicates nor anticipates
its domain separator, byte encoding, collision rule, allocation, or output.

Consequently F058 and F061 remain open. No group list, real split manifest,
patient identifier, outcome, or protected record is present here.
