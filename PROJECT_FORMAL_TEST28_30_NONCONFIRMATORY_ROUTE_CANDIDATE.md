## Why CP63 is revalidated rather than relaunched

CP63's accepted development run was executed under its exact frozen Python
3.11 pre-import environment and produced the immutable 16 × 2 receipt above.
The current local `.venv-m1/pyvenv.cfg` bytes no longer match CP63's historical
pre-import lock. This candidate does not weaken that lock, edit the environment,
or present a failed launch as a successful one. It instead validates the exact
accepted receipt embedded in the sealed CP63 fixture, validates the current
CP63 runner and independent-recomputation source pins, and states explicitly
that no fresh CP63 execution occurred inside the aggregate route process.

The whole-method lane separately performs a current fixed-seed Test-28
initializer/sampler exercise, so the aggregate demonstrates current synthetic
whole-method composition without rewriting CP63's historical custody.

## Trust boundary

The [route source](src/heterodiff/evaluation/formal_test28_30_nonconfirmatory_route.py)
uses only local deterministic inputs. It:

- opens pinned files as regular, single-link, mode-`0644` files through
  no-follow directory traversal;
- rejects noncanonical relative paths and noncanonical absolute root text;
- parses JSON with duplicate-key and non-finite-value rejection;
- verifies the full CP63 fixture raw hash before extracting its exact accepted
  execution and recomputation receipts;
- captures and verifies the Test-29/Test-30 wrapper bytes before compiling
  them in a controlled module namespace, ignoring and restoring preloaded
  module-cache entries, including explicit `None`;
- relies on the accepted wrapper to capture and compile its four exact parent
  sources before the 1,024-case execution;
- binds the whole-method output through its sealed machine-receipt raw hash and
  exact compact `route_binding`; and
- issues only exact frozen dataclass records with domain-separated canonical
  SHA-256 digests.

The [package validator](research/diagnostics/manuscript_v3_formal_test28_30_nonconfirmatory_route_candidate_v1.py)
is hash-first: it captures the candidate source and all registered files before
executing captured source bytes in a controlled namespace, recomputes the route,
compares it byte-for-byte with the [machine execution receipt](research/fixtures/manuscript_v3_formal_test28_30_nonconfirmatory_route_candidate_v1.json),
and reopens every file after validation. Preloaded or poisoned module-cache
objects do not become trusted project code.
