## Actual Test-29 and Test-30 path semantics

The transformed state, its selected-configuration digest, and its transform
digest are inputs to the path-input digest.  The path does not construct or
use the predecessor's independent frozen initial occurrences.

Each of exactly two macrosteps performs these accepted primitives:

1. build and validate exact CP23-addressed left increments for every active
   occurrence;
2. apply the accepted Test-30 stochastic-Heun half-step primitive;
3. validate an exact CP24-addressed central word;
4. run and validate the accepted finite-acyclic Test-29 oracle, route
   selection, and lineage advance;
5. apply the selected birth, death, or replacement with exact serial custody;
6. build and validate exact CP23-addressed right increments and apply the
   accepted Test-30 Heun primitive again.

Because the actual selected state is empty, step zero uses an explicit exact
rank-one zero-cardinality Test-29 birth fixture.  Word `2` selects route
`beta-zero-birth`.  Its new occurrence then receives the addressed right Heun
update.  Step one carries the same serial and coordinate forward, applies its
addressed left Heun update, and word `27` selects the accepted
`two-step-death` route.  The final state is empty again.  Tests also execute a
valid nonempty alternate initializer selection and prove that its selected
coordinate is the exact numerical input to the first Heun operation; changing
that coordinate changes the path report.

The local field `test28_initializer_admissible=true` means only this: the live,
owner-validated Test-28 development initializer result is structurally
admissible to this typed bounded path transform and was actually consumed by
the bounded path.  It does not mean that the operational source law is
admitted.  `formal_test28_production_law_admissible=false` remains explicit.
Formal Tests 28 and 29 remain `OPEN`; Formal Test 30 remains `PENDING`.
