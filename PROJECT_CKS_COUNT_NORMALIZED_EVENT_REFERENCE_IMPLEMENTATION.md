## 3. Exact generic construction

The caller supplies a finite anonymous alphabet
`E={e_1,...,e_m}`, a rational symmetric event Gram matrix `K`, a finite
configuration cap `N`, and positive rational values `a^2`, `b^2`, and
`sigma^2`. The reference accepts no kernel callback or module object. This is
important: an arbitrary callback could have effects or make the claimed Gram
matrix differ from the evaluated kernel.

The source checks exactly that:

- `K` is positive semidefinite;
- `K` is strictly positive on the nonzero zero-sum subspace, which is the
  finite-alphabet form of injectivity of the event probability mean map;
- the alphabet, matrix, cap, scales, tokens, configurations, and draw roster
  have strict built-in container and scalar types;
- all rational components and resource dimensions stay within fixed bounds;
  and
- every public consumption boundary reconstructs and revalidates the frozen
  specification, so low-level attribute replacement, subclasses, and
  bool-as-int substitutions cannot bypass constructor checks.

For a configuration `x`, let `n_x` be its count and let `p_x=x/n_x` when
`n_x>0`. The empty configuration has the zero event channel and no invented
probability. The exact direct-sum squared distance is

```text
d^2(x,y)
 = a^2 (n_x-n_y)^2
 + b^2 [ <m_px,m_px> + <m_py,m_py> - 2<m_px,m_py> ],
```

where every event-channel term involving the empty configuration is zero. The
outer kernel is

```text
k_Gamma(x,y) = exp(-d^2(x,y)/(2 sigma^2)).
```

Distance construction is exact rational arithmetic. A kernel value is the
canonical symbolic descriptor

```text
EXACT_SYMBOLIC_EXP_NEGATIVE_RATIONAL(q),
q = d^2(x,y)/(2 sigma^2).
```

No binary64 exponential is an authoritative kernel value. Descriptor equality
is exact rational equality of `q`. The generic theorem, rather than a rounded
finite matrix, governs positive definiteness and strict propriety.
`EXACT_SYMBOLIC_EXP_NEGATIVE_RATIONAL(q)` denotes the exact real number
`exp(-q)`; it is not itself a numerical approximation.

This implementation preserves multiplicity and is permutation invariant. A
positive count channel separates unequal counts, including proportional
duplicate configurations. The characteristic normalized event channel
separates equal-count configurations with different multiplicities. Empty
versus nonempty is always separated by the count channel.

## 5. Conditional kernel-score U-statistic

For caller-supplied configurations `X_1,...,X_R` and target `y`, the source
requires `2 <= R <= 128` and constructs the formal expression

```text
1/[R(R-1)] sum_{r != s} k_Gamma(X_r,X_s)
  - 2/R sum_r k_Gamma(X_r,y).
```

The off-diagonal term is unbiased for `E k_Gamma(X,X')` only under the
caller-owned premise that the within-method draws are conditionally i.i.d. The
reference neither tests nor asserts that premise. The score is a loss: lower is
better. Consequently, for this candidate, a positive paired value
`score_direct - score_guide` favors the guide. The implementation does not
claim that any empirical value will be positive. Every kernel occurrence is an
exact `exp(-q)` descriptor and every prefactor is an exact rational. Terms with
equal exponents are combined, zero coefficients are removed, and the remaining
terms are sorted by exponent. The authoritative output is this canonical
formal linear combination; no numerical score display is supplied.
The formal combination denotes the exact real sum of each rational coefficient
times `exp(-q)`. This implementation does not approximate that real value and
does not compute its sign, ordering, or comparison with another formal score.
`LOWER_IS_BETTER` records the theorem's loss convention, not a locally computed
numeric comparison.

Invalid score inputs are rejected by the score API through its exact type,
configuration, specification, and `R` checks. When `build_reference_report`
raises `CKSReportResourceError` after its internal score construction, only the
generated report lies outside the separate report-admission resource domain;
the refusal does not retroactively invalidate a formal score previously
returned by a separate score-API call. When standalone `report_sha256` raises
the same exception for an arbitrary report graph, it states only that the graph
is outside report-resource admission. It makes no statement that any score
input exists or is valid.
