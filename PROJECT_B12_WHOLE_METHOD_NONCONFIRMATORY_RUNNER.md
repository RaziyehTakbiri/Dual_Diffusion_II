# B12 whole-method nonconfirmatory runner candidate

## Decision boundary

This candidate implements and exercises one deterministic, offline,
nonconfirmatory whole-method composition.  It is an implementation candidate,
not an operational or scientific receipt.  It does not close B12, Formal Tests
28--30, any real residual predicate, any result slot, or either proposed
timetable checkbox by itself.  Registration remains subject to disjoint
independent review.

The candidate uses only caller-supplied fixture values and already accepted
local components.  It performs no network access, data loading, entropy
acquisition, training, upstream-package execution, production inference,
contact, tracker edit, or evidence-ledger edit.  All 50 real B12 residual
receipt slots remain `OPEN_RECEIPT_ABSENT`.

## Implemented composition

The public runner composes these implementation surfaces in one bounded call:

1. the accepted CP62 Test-28 `T28-M1-Q` exact score-provider and facade seam;
2. the v2 mixed-support initializer and fixed-budget SIR sampler with the
   caller-visible fixture seed `12a5228200019dae` and budget eight;
3. the supplied Test-29/Test-30 two-macrostep path with words `2` and `27`,
   including continuous left/right Heun applications, one replacement jump,
   one death jump, rolling lineage, and boundary-state continuity;
4. the corrected exact 22-row two-domain adapter manifest and two exact
   64-dimensional context encoders;
5. the exact F105 two-domain conditional CKS projection with 64 fixture draws
   in each domain;
6. an explicit namespace bridge from F105 identifiers `R4-RETAIL` and
   `R3-PHYS` to the B06/F144 identifiers `online-retail-ii` and
   `physionet-challenge-2012`;
7. the F139--F147 executable-configuration and F144 structural checkpoint
   seam at supplied development step 256, with an exact 128-group validation
   roster in each domain;
8. all eight external-author extension component obligations through the
   exact CSDI/PhysioNet and EditPP/Retail adapters and conditioning interfaces;
9. the closed-world component/evidence capsule, a paired in-memory
   `INTENT`/`OUTCOME` ledger, the exact-50 open B12 runner, and a separate
   recomputation implementation.

The F105-to-F144 bridge preserves a real namespace distinction: an F105
factory digest formed with `R4-RETAIL` or `R3-PHYS` is not byte-equal to the
normalized F144 subject formed with its B06 domain identifier.  The runner
records both digests and the explicit bijective mapping.  It does not silently
substitute one digest for the other.  F144 validation is structural only;
production history remains unauthenticated.

## Independent recomputation

The independent module parses only canonical, duplicate-free ASCII JSON with a
single terminal LF.  It does not import the primary runner.  It separately
re-executes the initializer, sampler, two-macrostep continuous/jump path,
corrected adapter/capsule surfaces, both F105/F144 bridges, and all eight
external-author interfaces.  The primary entrypoint refuses unless the
independent core bytes match its own core bytes exactly.

Process-local object-identity certificate digests are deliberately excluded
from the stable summary.  Stable semantic inputs, exact weights, configuration
digests, stream-state digests, source bindings, path reports, adapter records,
and structural receipts remain included.
