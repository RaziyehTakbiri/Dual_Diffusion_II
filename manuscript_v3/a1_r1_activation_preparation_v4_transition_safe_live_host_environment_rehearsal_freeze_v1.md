## Bounded child transport

The authority claims at most one environment-only child. The single deadline begins before `Popen`; the `Popen` call itself is not mechanically interruptible by that deadline, which is an explicit limitation. After process creation, stdin, stdout, and stderr are nonblocking and handled under the same deadline. Stdin records only the number of bytes accepted by the parent pipe and whether the exact request was fully written; it does not claim the child read or received those bytes.

Stdout and stderr counts are captured-prefix counts, never total-emission counts. Each stream separately records whether a captured count, EOF, and overflow were observed. Overflow retains at most the frozen bound plus one byte and sets a dedicated overflow Boolean. The exact privacy-safe request object is intentionally persisted in event 2. A validated privacy-safe structured child observation derived from stdout is embedded only in authoritative event 3; the terminal projection and published result carry its committed terminal state and raw/self-linked custody, not a duplicate observation object. Registered relative custody/source paths also intentionally persist in typed records. No separate raw transport capture, duplicate stream payload, unvalidated stream bytes, raw environment, raw identity, absolute user path, raw argv, or exception text is persisted.

After spawn, a terminal event is forbidden unless process reap and exit-code observation are both direct. A timeout can coexist with a later observed killed-process exit after reap. If kill/reap cannot be observed within the bounded cleanup, no event 3 is written; the child-claim event remains the terminal nonresumable fallback. Selector or pipe errors do not become fabricated timeouts. The transport failure code is recomputed in frozen order from spawn, full stdin, timeout absence, stdout EOF/bound, stderr EOF/empty, reap, zero exit, child contract, and postflight custody.
