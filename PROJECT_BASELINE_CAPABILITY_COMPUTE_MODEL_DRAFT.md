## 6. Matched-total-compute model draft

The draft uses an exact auditable resource ledger instead of an unqualified
wall-clock claim. For method `m` in domain `d`, let `n[m,d,p,k]` be the
nonnegative integer count of resource event `k` in phase `p`, and let
`w[d,k]` be a strictly positive exact rational calibration weight frozen on the
selected hardware before test access. The phases are:

- `PILOT`;
- `TUNING`;
- `FINAL_TRAINING`; and
- `CONFIRMATORY_INFERENCE`.

The resource-event vocabulary is:

- `BASE_FORWARD`;
- `BASE_BACKWARD`;
- `CONDITIONER_FORWARD`;
- `CONDITIONER_BACKWARD`;
- `GUIDE_EVALUATION`;
- `RESAMPLING_STEP`;
- `ODE_OR_SDE_STEP`;
- `DATA_ADAPTER_RECORD`;
- `METRIC_DRAW_EVALUATION`; and
- `OTHER_DECLARED_OPERATION`.

The exact draft cost is

`C[m,d] = sum_p sum_k n[m,d,p,k] * w[d,k]`.

Weights may be calibrated only by a predeclared microbenchmark on the frozen
hardware/environment. A weight cannot be changed per method, after seeing a
method's result, or to hide an expensive extension. Any operation not covered
by the fixed vocabulary must be declared under `OTHER_DECLARED_OPERATION`
before execution or the run is ineligible.

The primary pair receives identical predeclared ceilings `B[d]` in each domain
and the same patient/customer groups, conditioning cases, draws, base checkpoint,
precision policy, and metric workload. The ledger includes successful and
failed pilot/tuning/training/inference attempts, author extensions, and
preprocessing unique to a method. Unused allocation is not transferable and
no post-result top-up is allowed.

The scalar cost is necessary but not sufficient. The freeze must additionally
bind and report wall time, accelerator time, peak device/host memory, model
evaluation counts, persistent bytes, failure counts, and parameter counts.
Per-axis ceilings remain hard constraints even when scalar cost is below
budget. Realized-resource equality is not promised; fairness is equality of
the prospective ceiling and selection opportunity, with all realized use
reported.
